# 一、本次分享的核心主题

本次分享主要围绕：

> 如何让 AI Agent 在“可控边界”内安全地操作链上资产。

分享嘉宾是 Cobo Agentic Wallet 产品负责人 Johnny，重点讨论了：

- 为什么 AI Agent 需要链上支付能力；
- 为什么 Agent 操作资金会带来新的安全问题；
- MPC、Pact、Recipe 如何构成 Agent Wallet 的可信执行体系；
- Human-in-the-loop 为什么短期内仍然重要；
- Agent Economy 未来可能的发展方向。

这场分享让我第一次真正意识到：

> AI Agent 最大的问题不是“会不会做事”，而是“谁来约束它如何花钱”。

---

# 二、AI Agent 的发展路径

Johnny 把 AI 的发展过程分成了几个阶段。

## 1. Chatbot 阶段（2023）

这一阶段的 AI 主要是聊天机器人。

例如：

- ChatGPT
- Claude

它们主要负责：

- 回答问题；
- 辅助写作；
- 提供建议。

但真正执行任务的人依然是用户自己。

---

## 2. Copilot 阶段（2024）

这一阶段 AI 开始参与复杂工作流。

例如：

- Cursor
- Claude Code

AI 已经能够：

- 帮助生成代码；
- 提供完整方案；
- 规划执行步骤。

但仍然需要：

> 人类逐步确认和批准。

---

## 3. Agent 阶段（2025～）

这一阶段 AI 不再只是“聊天”。

而是：

- 可以后台持续运行；
- 能自动完成任务；
- 可以长期执行工作流。

人类只需要：

- 给目标；
- 给边界；
- 给规则。

然后 Agent 自己执行。

---

## 4. 当前真正的问题

AI 已经越来越像“数字执行者”。

但目前还缺少：

> 一套可信、安全、可约束的资金执行系统。

因为：

- 链上交易不可逆；
- 私钥权限极高；
- Agent 可能产生幻觉；
- Prompt 可能被攻击。

所以：

> “如何让 Agent 安全花钱”
已经变成 AI + Web3 最核心的问题之一。

---

# 三、为什么 Agent 动钱会变危险

分享中提到了几个非常典型的问题。

---

## 1. Prompt Injection（提示词注入）

即：

外部内容影响 Agent 的判断。

例如：

用户本来要求：

> “只能花 100 美元。”

但 Agent 在执行过程中：

- 被恶意 Prompt 干扰；
- 或模型产生幻觉；

最后可能：

- 转出更多资产；
- 调用了错误合约；
- 执行了危险操作。

### 核心理解

自然语言并不是强约束。

Prompt 只能“建议 AI”。

但不能真正“锁死权限”。

---

## 2. Shadow Operations（影子操作）

这是我觉得非常危险的一类问题。

Agent 可能：

- 在用户不知道的情况下；
- 创建额外 EOA 地址；
- 先把钱转出去；
- 再继续执行操作。

这样会导致：

> 原本所有的权限控制全部失效。

因为资金已经离开受控钱包。

---

## 3. Unscoped Authority（无限权限）

如果不给 Agent 设置明确权限：

那么：

- 它理论上能操作全部资金；
- 一次失误可能导致资产全部转出。

这和传统钱包最大的区别是：

> Agent 可以“自主连续执行”。

风险会被无限放大。

---

## 4. Zombie Permissions（僵尸授权）

这和 DeFi 常见授权问题很像。

例如：

用户曾授权某协议无限额度。

后来：

- 合约被攻击；
- 协议出现漏洞；

那么：

> 即使用户已经不用这个协议，
授权依然有效。

这就是长期风险暴露。

---

# 四、Cobo 提出的解决思路

Cobo 的核心目标：

> 不是给 Agent 一个钱包，
而是给 Agent 一套“可控执行系统”。

他们主要用了三个核心结构：

| 组件 | 作用 |
|---|---|
| MPC | 解决私钥安全 |
| Pact | 解决权限边界 |
| Recipe | 解决执行正确性 |

---

# 五、MPC：解决私钥安全问题

## 1. 什么是 MPC

MPC（Multi-Party Computation）：

是一种“多方共同签名”的钱包方案。

私钥不会完整出现在单一设备里。

而是：

- Human 持有一部分；
- Agent 持有一部分；
- Cobo 持有一部分。

任何单方：

> 都无法单独转移资产。

---

## 2. 为什么比传统钱包更安全

传统 EOA 钱包：

谁拿到私钥，
谁就能转走全部资产。

但 MPC：

即使某一方泄露，
也无法单独完成签名。

---

## 3. 2-of-2 模式

分享中提到了两种场景。

### Agent + Cobo

适用于：

Agent 自动执行任务。

但：

- 必须满足 Pact 条件；
- Cobo 会再次校验。

---

### Human + Cobo

适用于：

用户自己操作大额资金。

例如：

- 大额转账；
- 高风险操作。

---

# 六、Pact：真正的授权边界

这是我觉得本场最核心的概念。

## 1. Pact 是什么

Pact 可以理解为：

> “AI Agent 的可执行授权协议”。

它会明确规定：

- 能做什么；
- 不能做什么；
- 什么时候停止。

---

## 2. Pact 的四个核心部分

### （1）Intent（用户意图）

例如：

> “ETH 低于 2000 美元时买入。”

这是目标。

---

### （2）Execution Plan（执行计划）

AI 会把意图转成：

- 调用哪个合约；
- 使用哪个 Token；
- 如何完成交易。

---

### （3）Policy（风控规则）

这是最重要的一层。

包括：

- 金额限制；
- 白名单；
- Token 限制；
- 合约限制；
- ABI 参数限制；
- 链限制。

本质上：

> 是给 Agent 画“边界”。

---

### （4）Completion Condition（完成条件）

例如：

- 到期自动失效；
- 达到金额自动停止；
- 完成任务后自动 revoke。

这是为了避免：

> Zombie Permissions（长期授权风险）。

---

# 七、Recipe：让 Agent “知道怎么做”

Johnny 提到：

现在的大模型其实：

> 并不真正懂链上执行。

它们容易：

- 构造错误参数；
- 调用错误接口；
- 产生幻觉。

---

## 1. Recipe 的作用

Recipe 类似：

> “链上任务知识胶囊”。

里面会封装：

- 合约地址；
- ABI；
- 调用逻辑；
- 风控规则；
- 执行路径。

---

## 2. 为什么重要

因为：

AI 不再是“临场发挥”。

而是：

> 按照已验证路径执行。

这样能大幅降低：

- 幻觉；
- 错误调用；
- 错误授权。

---

## 3. 已支持的协议

目前支持：

- Aave
- Uniswap
- Hyperliquid
- Polymarket

等主流协议。

---

# 八、Human-in-the-loop 为什么还重要

分享中反复强调：

> 短期内，人类审批仍然不可缺少。

原因包括：

- Agent 还不够稳定；
- 基础设施不成熟；
- 模型仍会幻觉；
- 链上资金不可逆。

所以：

目前最合理的模式是：

> Agent 自动执行，
Human 最终审批。

# 九、小额免密支付的思路

Q&A 里有一个我觉得很有意思的话题。

有人提出：

是否能让 Agent 自动购买：

- API Token；
- AI 服务额度；
- 小额订阅。

例如：

余额不足时：

Agent 自动充值 USDC。

---

## 这个场景为什么合理

因为它具备：

- 高频；
- 小额；
- 固定目标；
- 风险较低。

所以非常适合：

> 自动化 Agent 支付。

---

## 如何控制风险

可以通过 Pact 限制：

- 单次金额；
- 每日次数；
- 总额度；
- 指定收款地址。

这样即使自动执行：

风险也会被限制在很小范围。

# 十、Agent Economy 为什么可能更适合链上

分享中还讨论了：

> Agent 支付一定要发生在链上吗？

Johnny 的观点是：

未来：

- Web2 支付；
- Crypto 支付；

会长期并存。

但链上更适合：

- 自动化；
- 全球结算；
- 稳定币支付；
- Agent-to-Agent（A2A）支付。

因为：

区块链天然具备：

- 可编程；
- 可追踪；
- 自动执行；
- 无国界结算。

# 十一、我对这次分享的理解

这次分享让我意识到：

> Agent Wallet 本质上不是钱包问题，
而是“权限系统”问题。

过去 Web3 的核心问题是：

- 私钥安全；
- 合约安全。

但 AI Agent 出现后：

新的核心问题变成：

- 如何限制 AI；
- 如何让 AI 在边界内执行；
- 如何让授权可以审计和撤销。

我认为：

未来 AI + Web3 的重点，
可能不是让 Agent 更聪明，

而是：

> 如何建立“可信执行层”。
