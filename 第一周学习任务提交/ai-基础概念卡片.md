# Week 1｜AI 向任务｜AI 基础概念卡片整理

## 一、LLM（Large Language Model）

LLM 可以理解成：

“大型语言模型”。

它本质上属于：

一种通过大量文本训练出来的 AI 系统。

LLM 的核心能力包括：

- 理解文字
- 生成文字
- 总结内容
- 编写代码
- 进行对话

目前常见的 LLM 包括：

- ChatGPT
- Claude
- Gemini

等。

例如：

我今天让 AI 帮我整理 Web3 学习笔记，

本质上就是：

LLM 在理解内容后重新生成结构化文字。

但 LLM 并不真正“理解世界”。

它更像是在：

根据概率预测：

“下一句话最可能是什么”。

因此：

LLM 可能出现：

- 幻觉
- 错误信息
- 编造内容

（Hallucination：AI 编造不存在的信息。）

[误区：很多人会以为 LLM 真正拥有人类思考能力，但它本质上仍然是概率预测模型。]

---

# 二、Prompt

Prompt 可以理解成：

“给 AI 的指令”。

用户告诉 AI：

- 想做什么
- 输出什么
- 使用什么格式

这些内容都属于 Prompt。

例如：

“帮我把这份 PPT 整理成 GitHub 学习笔记”

就是一个 Prompt。

Prompt 会直接影响：

AI 的输出质量。

Prompt 越明确，

AI 输出通常越稳定。

例如：

只说：

“帮我总结”

可能结果会很模糊。

但如果说明：

- 使用 Markdown
- 学生口吻
- 段落式结构
- 包含解释

AI 输出就会更准确。

（Prompt：用户给 AI 的输入指令。）

[误区：很多人觉得 AI 不好用，其实很多时候是 Prompt 不够明确。]

---

# 三、Context Window

Context Window 可以理解成：

AI 一次能够“记住”的内容范围。

AI 并不是无限记忆。

它只能在当前上下文窗口里：

读取与理解内容。

如果内容超出窗口，

AI 就可能：

- 遗忘前文
- 丢失上下文
- 理解错误

例如：

如果我一次给 AI 上传几十页 PPT，

但上下文超出限制，

AI 后面可能忘记前面的内容。

因此：

长任务通常需要：

- 分段处理
- 总结记忆
- 压缩上下文

（Context Window：AI 一次能够处理的信息范围。）

[误区：很多人以为 AI 会永久记住全部聊天内容，但实际上上下文存在容量限制。]

---

# 四、Workflow

Workflow 可以理解成：

“AI 的任务流程”。

它强调的不是：

单次回答。

而是：

多个步骤自动串联完成。

例如：

我现在整理 Web3 学习笔记的流程：

图片 → OCR → AI 总结 → Markdown → GitHub

这其实就是一个 Workflow。

AI Workflow 通常包括：

- 输入
- 处理
- 调用工具
- 输出结果

很多 AI 自动化系统，

本质上都是 Workflow。

（Workflow：任务按照固定步骤自动执行的流程。）

[误区：很多人觉得 AI 只是聊天工具，但实际上 AI 更大的价值在自动化工作流。]

---

# 五、Agent

Agent 可以理解成：

“能够主动执行任务的 AI”。

普通聊天 AI：

主要负责回答问题。

但 Agent 不只是聊天。

它还能够：

- 调用工具
- 自动执行命令
- 修改文件
- 分析结果
- 自动重试

例如：

Claude Code、

OpenAI Codex、

Hermes Agent

都属于：

Agent 类工具。

Agent 的核心特点包括：

- 有目标
- 能行动
- 会观察结果
- 能自动修正

因此：

Agent 更像：

“AI 执行者”。

（Agent：能够自主完成任务的 AI 系统。）

[误区：很多人会把聊天机器人和 Agent 混为一谈，但 Agent 更强调执行能力。]

---

# 六、Tool Use（工具调用）

Tool Use 可以理解成：

“AI 使用外部工具”。

因为：

LLM 本身只能生成文字。

它并不能直接：

- 搜索网页
- 修改代码
- 运行程序
- 调用 API

所以：

AI 需要通过 Tool Use 获得外部能力。

例如：

现在很多 AI 可以：

- 搜索网页
- 运行 Python
- 调用 GitHub
- 操作数据库

本质上都属于：

Tool Use。

例如：

Claude Code 能直接修改代码文件，

就是 AI 在调用开发工具。

（Tool Use：AI 调用外部工具完成任务。）

[误区：很多人以为 AI 天生能操作电脑，但实际上它通常需要工具接口。]

---

# 七、AI Coding

AI Coding 可以理解成：

“AI 辅助编程”。

目前 AI 已经能够帮助完成：

- 写代码
- 修复 Bug
- 解释项目
- 自动补全
- 重构代码

例如：

Cursor、

Claude Code、

Copilot

都属于 AI Coding 工具。

AI Coding 的核心变化是：

程序员开始从：

“纯手写代码”

转向：

“人与 AI 协作开发”。

但目前 AI Coding 仍然存在：

- 理解错误
- 架构混乱
- 安全问题
- 幻觉代码

因此：

人类仍然需要：

检查与审核代码。

（Bug：程序中的错误。重构：优化代码结构但不改变功能。）

[误区：很多人觉得 AI 会完全取代程序员，但目前 AI 更像开发辅助工具。]

---

# 八、Guardrails

Guardrails 可以理解成：

“AI 的安全限制机制”。

因为：

AI Agent 一旦拥有：

- 钱包
- API
- 文件权限
- 自动执行能力

如果没有限制，

就可能：

- 误操作
- 滥用权限
- 造成资产损失

因此：

系统通常会设置：

- 白名单
- 金额限制
- 人工确认
- 权限范围
- 风险检查

这些都属于：

Guardrails。

例如：

AI 只能转账小额资产，

或者必须人工确认后才能执行。

（Guardrails：限制 AI 行为范围的安全机制。）

[误区：很多人认为 AI 越自由越强，但实际上没有限制的 AI 风险非常高。]

---

# 九、Tracing

Tracing 可以理解成：

“记录 AI 的执行过程”。

因为：

AI Agent 经常会：

- 调用工具
- 多步推理
- 自动执行任务

如果不记录过程，

用户就很难知道：

AI 为什么会出错。

因此：

很多 Agent 系统都会保存：

- 调用记录
- 推理过程
- 工具执行日志
- 错误信息

这些内容属于：

Tracing。

例如：

AI 调用了哪个 API、

修改了哪些文件、

为什么失败，

都需要记录。

（Tracing：记录 AI 执行路径与行为日志。）

[误区：很多人只关注 AI 输出结果，但复杂系统更需要过程可追踪。]

---

# 十、Human-in-the-loop

Human-in-the-loop 可以理解成：

“人类参与 AI 决策”。

目前很多 AI 系统，

并不是：

完全自动化。

而是：

AI 提供建议，

人类负责最终确认。

例如：

AI 自动生成代码后，

程序员仍然需要审核。

AI 自动生成交易后，

用户仍然需要签名确认。

因此：

Human-in-the-loop 属于：

“人类保留最终控制权”。

这也是目前很多 AI Agent 的主流安全方式。

（Human-in-the-loop：人类参与 AI 执行流程的机制。）

[误区：很多人觉得未来 AI 会完全脱离人类，但目前大部分系统仍然需要人工监督。]

“一个聊天机器人”。

- 工具能力
