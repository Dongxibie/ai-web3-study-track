## 为什么这次复核很关键

这次互动看起来是"小决策",但它正好对应 week 1 卡片里讲的几个概念,我自己回头看才意识到:

| 卡片里的概念 | 这次互动怎么体现 |
| --- | --- |
| **Human-in-the-loop** | Agent 没有自作主张 —— 它在不确定时主动停下来问我,把"最终决策权"保留在人手里 |
| **Guardrails** | 这是 agent 给**自己**加的护栏(`AskUserQuestion` 工具) —— 它判断"目录位置 / 日期"是用户偏好型决策,不是事实型问题,所以拦下来 |
| **Tracing** | 整个互动都有 commit history 可追溯:`27052a8`(初版)→ `bf1012e`(按我反馈删除第 12 节),不是覆盖式修改 |
| **Workflow** | 上传文件 → 写 daily-note → 加 Demo 区链接,这是一个三步 workflow,agent 把它拆成可确认的子步骤,而不是一次性 push 所有内容 |

## 反例 · 我没拦住、事后才想到的地方

诚实记录两个 agent **没问我**就自己决定了的点:

1. **commit message 的措辞**:agent 自己写了 `docs(week1): add AI 基础概念卡片整理 ...`,我事后觉得也行就没改 —— 但严格说这种"对外可见的产物"也应该让我先看。下次要让它把 commit message 也作为待确认项。
2. **daily-note 里的「今日学习主题/明日计划」**:这两段是 agent **基于卡片内容反推**的占位文字,我当时没纠正 —— 但其实今天我除了整理卡片之外,还做了别的事(这次 Learning Agent Setup 作业本身!),应该追加进去。明天我会回去补。

## 结论

**结论一**:好的 agent 不是"问得越少越聪明",而是"能识别哪些事不该自己决定"。

**结论二**:作为人类用户,**复核动作要在 agent 动手前发生**,而不是等它把文件写好再撤回 —— 一旦写到 GitHub,即使能 force-revert,commit history 也已经留痕(本仓库还从不 force-push,所以记录是真实可追溯的)。

**结论三**:对自动化要保留**未来感知层**。今天 agent 没问我的「commit message」「日报占位文字」,下次我会主动把它们也列进待确认项。
